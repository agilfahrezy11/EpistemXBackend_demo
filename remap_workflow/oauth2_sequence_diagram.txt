KEY POINTS:
===========

1. AUTHORIZATION CODE FLOW
   - Frontend gets authorization code from Google
   - Backend exchanges code for tokens
   - Tokens stored server-side (secure)

2. TWO TYPES OF CREDENTIALS
   - Service Account: For EE and temp Drive operations
   - User OAuth2: For accessing user's personal Drive

3. OFFLINE ACCESS
   - Refresh token allows backend to work without user present
   - Essential for long-running export tasks

4. SESSION MANAGEMENT
   - Credentials stored in server session (GAE Datastore)
   - Automatic token refresh on every request
   - Session cleared if refresh fails

5. BACKGROUND TASK
   - Export queued immediately (avoids 60s timeout)
   - Worker uses stored credentials
   - Frontend polls for status updates

6. DRIVE OPERATIONS
   - Export to temp location (service account)
   - Grant user access to temp files
   - Copy to user's Drive (user credentials)
   - Cleanup temp files


SECURITY:
=========

✓ Credentials never exposed to frontend
✓ Tokens stored server-side only
✓ HTTPS required for all OAuth flows
✓ Limited scopes (Drive + email only)
✓ Refresh tokens can be revoked by user
✓ Session backed by encrypted datastore
